//风控系统逻辑
风控系统的职责是在交易各环节检测和拦截风险,保护用户资产、交易所安全、市场公平。它不是单一环节,而是贯穿下单前→实时→成交后→市场→账户的分层防御。按你的风格梳理:
[下单前风控 Pre-trade] —— 拦截,毫秒级
用户WS委托 --> 风控引擎规则校验
  ├─ 余额/冻结检查(买单冻结计价币/卖单冻结基础币够不够)
  ├─ 价格保护(偏离市场价±X%拒绝,防胖手指)
  ├─ 限频(下单/撤单频率上限,防刷单DoS)
  ├─ 单笔量上限 + 持仓限额(用户/symbol/总)
  ├─ 权限(黑白名单/订单类型/杠杆/币种)
  ├─ 自成交预检(和用户现有挂单是否成交)
  └─ 合约保证金检查
  --> 通过 --> 写Kafka①委托(进交易系统)
  --> 拒绝 --> ack失败给用户,不进撮合

[实时风控 Real-time] —— 监控+强平,秒级
委托/成交流 --> 风控引擎实时计算
  ├─ 持仓/净敞口超限 --> 限制新单/强平
  ├─ 撤单率监控(高频撤单疑似操纵 --> 限制)
  ├─ 自成交实时检测 --> 取消/标记
  ├─ 异常交易模式(对敲/刷单/操纵 --> 告警/限制)
  └─ 合约维持保证金不足 --> 强平引擎自动强平

[成交后风控 Post-trade] —— 对账+提现
成交 --> 消费组成交
  ├─ 余额变更校验(不为负,异常拦截)
  ├─ 资金流水对账(成交 vs 余额流水一致)
  ├─ 大额/异常成交告警
  └─ 提现风控(限额 + 地址白名单 + 异常提现人工审核/冻结)

[市场风控 Market] —— 保护全市场
本所行情 + 第三方行情 --> 市场风控
  ├─ 价格熔断(N分钟涨跌超X% --> 暂停交易)
  ├─ 偏离外部告警(本所 vs 第三方超阈值 --> 告警/做市干预)
  ├─ 全局自成交检测
  ├─ 操纵检测(spoofing幌骗/layering分层 --> 告警/限制)
  ├─ 流动性监控(盘口深度异常)
  └─ 系统风控(撮合延迟/lag --> 告警/暂停)

[账户风控 Account]
用户行为 --> 账户风控
  ├─ 异常登录(异地/暴破 --> 锁定/二次验证)
  ├─ 设备指纹/IP风控
  ├─ API key异常调用监控(异常频率/未授权操作)
  └─ KYC/AML(可疑交易上报/冻结)

[合约风控](如有合约/杠杆)
  ├─ 保证金监控(维持保证金率 --> 强平)
  ├─ 爆仓引擎(自动强平)
  ├─ 穿仓处理(亏损超保证金 --> 风险准备金/穿仓分摊)
  └─ 资金费率结算

下单前风控的规则要轻(本地缓存用户状态,快查),重规则放实时层(异步,不阻塞下单)。

数据源

- 用户实时状态(余额/持仓/挂单)← 交易/资金系统,Redis 热缓存 + 本地缓存。
- 行情(本所 + 第三方)← 行情系统 + 第三方采集服务。
- 历史行为 ← ClickHouse(成交/委托历史,撤单率/异常模式)。

关键要点

1. 硬拦截 vs 软告警 vs 人工审核

- 硬拦截:下单前(余额/价格/限频/权限)直接拒绝,不进撮合。
- 软告警:实时/市场层(异常模式/偏离)告警,人工介入或滞后限制(不实时拦,避免误杀)。
- 人工审核:提现/可疑交易/大额,冻结待审。
- 别把所有规则都设硬拦(误杀正常用户),高风险/明确的才硬拦,模糊的软告警+人工。

2. 规则引擎可配置

- 规则热更新(不改代码、不重启),运营可调阈值(熔断比例/限频数/持仓限额)。
- 做市商账号专属配置(限频放宽,价格保护保留),和普通用户分账号规则。

3. 风控 HA + 降级策略

- 风控宕机 = 要么交易停(拒绝所有),要么裸跑(放行+告警)。两种都不好。
- 风控引擎 HA(主备),下单前风控超时降级(默认放行+告警,或默认拒绝,看风险偏好)。
- 风控自身不能成单点瓶颈(下单前风控慢=拖累全站下单)。

4. 误拦 vs 漏拦平衡

- 误拦正常用户(体验差,用户流失)vs 漏拦风险(资损)。
- 下单前规则偏严(明确风险才拦),实时/离线偏宽(告警为主),逐步收紧(多次告警→限制)。

5. 自成交预防(容易漏)

- Pre:下单前检查用户现有挂单,若会和自己成交 → 拒绝/修改。
- Realtime:实时检测自成交 → 取消成交/标记(防洗盘)。
- 全局:跨用户自成交(关联账户互敲)→ 离线分析挖掘(同IP/同设备/资金关联)。

6. 操纵检测(spoofing/layering)

- 幌骗(spoofing):大单挂出影响价格,成交前撤(不 intend 成交)→ 检测高频挂撤+大单未成交。
- 分层(layering):多档挂单影响盘口,成交前撤 → 检测多档挂撤模式。
- 离线分析为主(实时难判定),告警+人工+限制。

和你已有系统的关系

你之前设计的:
- 交易系统"用户WS→风控→Kafka①" = 下单前风控(Pre)。
- 做市系统"做市风控(库存/撤单率/止损)" = 做市商自己的风控(可并入风控系统的做市账号规则)。
- 行情系统"本所偏离外部告警" = 市场风控(偏离外部)。
- 第三方采集 = 市场风控的数据源(偏离检测)。

风控系统把这些整合成一个独立的分层防御系统,接入交易/行情/做市/账户各环节,规则引擎统一管理。下单前风控是你已有的,扩展实时/成交后/市场/账户层,就是完整风控。

最核心的几条

1. 分层防御:Pre(拦截)→ Realtime(监控强平)→ Post(对账)→ Market(熔断操纵)→ Account(登录API),各层职责不同、延迟不同。
2. 下单前硬拦 + 实时软告警:明确风险硬拦,模糊风险告警+人工,平衡误杀和漏拦。
3. 规则引擎可配置,运营调阈值,做市商分账号规则。
4. 风控 HA + 降级策略,不能成单点/瓶颈。
5. 自成交预防 + 操纵检测,Pre 实时离线三层(实时难,离线挖掘关联账户)。
6. 合约专属:保证金/强平/穿仓/资金费率(如做合约)。
